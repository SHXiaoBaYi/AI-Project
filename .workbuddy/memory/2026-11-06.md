## 续接昨日（额度耗尽中断）的 v28 浏览器采集联调收尾

- 昨日 v28 端到端冒烟测试（建临时账号→触发真实浏览器登录）被额度打断，且暴露了一个代码 bug：模拟登录在 `LOGIN_NAVIGATE` 阶段崩溃，报 `Unexpected token "=" while parsing css selector "[data-testid='to_login_button'], text=/^登录$/"`。
- 根因：把「CSS 选择器 + `text=` 正则」用逗号拼成**单个字符串**交给 Playwright，会被当成纯 CSS 解析而抛错。`loginRequiredSelectors`/`dismissSelectors` 之所以正常，是因为它们本来就是按条目拆分的 `List`，逐个传入 `page.locator()`。
- 修复（已提交 `16776bc`，mvn compile 通过、端到端复测通过）：
  - `GeoBrowserProbeProperties`：`loginEntrySelector`/`loginSubmitSelector`/`loginCaptchaSelector` 三个单字符串字段 → 候选选择器 `List`，与 `loginRequiredSelectors` 一致。
  - `GeoBrowserProbeService`：新增 `clickFirstVisible(page, List, diag, key)` 与 `isAnyVisible(page, List)` 重载，逐条尝试；单条语法/匹配失败不影响后续候选；登录入口/提交/验证码检测全部走列表。
- 复测结论（建临时账号 v28_smoke3→触发登录→删除）：
  - `CSS_CRASH_STILL_PRESENT: False`（崩溃消失）。
  - `captchaDetected: True`（验证码/扫码检测从「异常被吞、静默失效」恢复为正常命中）。
  - 豆包返回准确可执行提示：「该平台当前只提供扫码/短信验证码登录…请把该账号登录方式改为 STORAGE_STATE，并用 scripts/export-geo-storage-state.sh 人工导出登录态」——豆包默认就是扫码登录，密码模拟登录路线本就不适用，正确路径是人工导出 storageState。
