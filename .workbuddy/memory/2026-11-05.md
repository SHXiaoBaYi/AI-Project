## v2 浏览器采集联调收尾（15:4x–16:0x）
- 用户要求「借鉴模力指数实现探测链接/截图」→ 已按 C 端网页版浏览器采集落地（Java 内置 Playwright 1.64.0 + 本机 Chrome）。本轮解决联调阻塞并补齐可用性。
- **坑3（重要）**：Playwright Java `Playwright.create()` 会顺带跑 `cli.js install` 下载 Chrome for Testing（cdn.playwright.dev 国内卡死，install 子进程最长等 10 分钟），导致首次试跑 225s 外层超时、`TimeoutException`、诊断为空。修复：`executable-path` 非空时用 `Playwright.create(new Playwright.CreateOptions().setEnv(Map.of("PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD","1")))`；同时把外层超时改成返回带 `stage` 的诊断快照（共享 synchronizedMap LinkedHashMap）。本机 Chrome 启动 ≈2s。
- **坑4**：未登录豆包落地页有 `data-testid=to_login_button` + 推广弹窗，提交问题被重定向 `?from_logout=1`；DOM 兜底把无障碍拖拽提示（"To pick up a draggable item…"）当成回答，`PAGE_URL` 被当成回答链接，产生假成功。修复：`GeoBrowserProbeProperties.PlatformProfile` 新增 `login-required-selectors` / `dismiss-selectors` / `answer-reject-patterns` 三组可配置信号；命中登录标志直接返回「请上传 storageState」并附登录墙截图；回答命中 UI 文案或 <60 字一律判失败；失败时不再输出 probeUrl。
- 实测：未登录试跑 5s 内返回明确错误 + 截图 + 完整 diagnostic；用本地 mock C 端页全链路自测通过（answerSource=SELECTOR / reasoning 45字 / citations 1 / probeUrlSource=OFFICIAL_SHARE / BROWSER_SHOT / stage=DONE）。截图静态路径为 `/api/uploads/geo/auto-monitor/{date}/*.png`（注意 context-path=/api，直接 /uploads 是 404）。
- 新增 `scripts/export-geo-storage-state.sh` + `scripts/GeoStorageStateExporter.java`：有头 Chrome 人工登录 → 回车导出 Playwright storageState JSON 到 `BackEnd/uploads/geo/auto-monitor/state/{平台名}.json`。**脚本必须用 Maven 生成的完整 runtime classpath**（`mvn dependency:build-classpath`），只手工拼 playwright/driver/driver-bundle 三个 jar 会解压不全报 `Cannot find module './lib/bootstrap'`。Git Bash 里 Java 不认 `/c/...`、`/d/...`，需 `cygpath -m` 转 Windows 路径，并加 `-Dstdout.encoding=UTF-8` 避免中文乱码。
- 前端 `npx tsc -b` 仍有历史遗留报错（style-pack / yearly-target / hr / train / workbench 等），与 geo/auto/** 无关；用 `vite build` 校验产物。
- 结论：机制已完整可用，但真实平台的回答/官方分享链接/思考过程/引用信源**必须先导入登录态**；登录态会过期，失效重新导出。
