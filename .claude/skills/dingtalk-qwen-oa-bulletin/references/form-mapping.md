# 行政通报 · processCode 与控件映射

供千问办公 Agent 在填表时对照。对接本企业后务必补全「本企业映射」。

## 固定配置

```yaml
bulletin:
  formName: 行政通报
  processCode: '' # 必填，例 PROC-XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX
  deptId: '' # 可选，发起部门
  confirmPolicy: always # always | never（never 仅当用户显式授权自动提交）
```

也可用同级目录旁的 `config.local.yaml`（由 `config.example.yaml` 复制，勿提交密钥）。

## 查找 processCode

在千问办公中（钉钉连接器已登录）说：

```text
列出我可发起的审批表单，找出名称含「行政通报」的，给出 processCode
```

将结果填入上方 `processCode`。

## 控件语义 → 填法

| 语义 | 可能 label | 值类型提示 |
|------|-----------|------------|
| 标题 | 标题、通报标题 | 短文本，建议带【行政通报】前缀 |
| 正文 | 通报内容、事由、详细说明 | 多行文本 |
| 类型 | 通报类型、类别 | 单选，value 与 Schema 一致 |
| 级别 | 紧急程度、级别 | 单选 |
| 适用范围 | 适用范围、接收范围 | 部门/人员控件按 Schema |
| 生效日 | 生效日期、通报日期 | 多为 yyyy-MM-dd |
| 附件 | 附件 | 先上传再按连接器要求写入 |

## 创建参数示意

```json
{
  "processCode": "PROC-XXXX",
  "formComponentValues": [
    { "name": "标题控件id", "value": "【行政通报】关于…-2026-03-24" },
    { "name": "正文控件id", "value": "一、事项说明…\n二、要求…" }
  ]
}
```

实际参数名以钉钉连接器当前工具的 Schema 为准。

## 排错

| 现象 | 处理 |
|------|------|
| 提示无钉钉工具 | 扩展 → 连接器 → 钉钉登录；新建对话 |
| 搜不到行政通报 | 检查发起权限、模板是否停用 |
| 选项非法 | 使用 Schema 枚举值 |
| 无发起类工具 | 按 SKILL.md：产出填表清单，说明需管理员开通或用户手工提交 |
