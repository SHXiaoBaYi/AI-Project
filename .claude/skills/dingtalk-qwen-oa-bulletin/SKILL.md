# 行政通报 OA 审批（千问办公 · 钉钉）

本 Skill 安装到**千问办公**后使用。通过已授权的**钉钉连接器**，完成「行政通报」审批的定位、填表、确认与发起。

## 安装位置

- 目标运行环境：千问办公（QwenWork），技能目录一般为 `~/.qwenworkcn/skills/dingtalk-qwen-oa-bulletin/`
- 安装方式见同目录 [INSTALL.md](INSTALL.md)
- **必须先**在千问办公「扩展 → 连接器」中安装并登录**钉钉**连接器；未连接钉钉时不得假装已发起审批

## 前置检查（每次任务开始）

1. 确认钉钉连接器可用；不可用则引导用户：扩展 → 连接器 → 市场 → 钉钉 → 登录授权，然后**新建对话**再试。
2. 确认企业 OA 存在可发起的「行政通报」模板。
3. 写操作（真正创建审批实例）前必须向用户展示摘要并获得明确确认（用户说「直接发 / 不用确认」时可跳过）。

## 本企业必填项（硬性）

以下 **11 项全部必填**，缺一不可发起。取值须与 OA 表单 Schema 选项/控件类型一致，禁止臆造枚举值。

| # | 字段 | 说明 / 上下文常见来源 |
|---|------|----------------------|
| 1 | 通报类型 | 单选/选项；对话、纪要、制度条款中常有「类型」「属于…通报」 |
| 2 | 通报责任人 | 人员；@某人、姓名、工号；可用钉钉通讯录解析 |
| 3 | 责任人所属部门 | 部门；可从责任人钉钉档案/通讯录反查，勿瞎填 |
| 4 | 通报关键词 | 短词/标签；可从事由提炼 1～若干词，提炼后需在摘要中标明「已自动提炼」 |
| 5 | 提议人 | 人员；常为当前用户或对话发起人；可用「我」→ 当前登录人 |
| 6 | 提议积分 | 数字；对话里「积 X 分 / +X」；无则必须追问，禁止默认 0（除非用户明确说 0） |
| 7 | 通报事由 | 多行文本；事由、经过、说明；可从长文/纪要摘要，但勿歪曲事实 |
| 8 | 责任类型 | 单选/选项；如个人/部门等，以 Schema 为准 |
| 9 | 通报分类 | 单选/选项；以 Schema 为准 |
| 10 | 通报数量 | 数字；次数、件数等 |
| 11 | 奖惩情况 | 文本或选项；奖励/处罚内容、金额、条款等 |

Schema 中若还有其它必填控件（附件、标题等），同样按「先上下文、再追问」处理。控件 id 对照见 [references/form-mapping.md](references/form-mapping.md)。

## 执行流程（严格按序）

```
行政通报审批进度:
- [ ] 1. 自动抓取上下文 → 预填 11 项必填（及 Schema 其他必填）
- [ ] 2. 列出已填充 / 缺失项；仅对缺失项向用户补全（一次问清）
- [ ] 3. 用钉钉连接器定位「行政通报」模板 (processCode)
- [ ] 4. 拉取表单 Schema，校验选项与控件类型
- [ ] 5. 按 Schema 组装 formComponentValues（禁止臆造控件 id / 选项）
- [ ] 6. 如有自选审批人节点 → 流程预测并请用户选定
- [ ] 7. 展示完整字段摘要，等待确认
- [ ] 8. 创建审批实例，回报 instanceId / 查看路径
```

### 1. 先自动抓取上下文（优先于追问）

启用本 Skill 后，**先扫描当前对话与可用上下文**，再开口问人。来源按优先级：

1. **本轮用户话术**（含粘贴的通报草稿、制度摘录、聊天记录）
2. **同任务历史消息**（用户此前已说过的姓名、部门、分数等）
3. **用户 @ / 引用的文件、图片 OCR、纪要、表格**（若千问办公已提供）
4. **钉钉连接器可读信息**（当前登录人作默认提议人；按姓名查责任人与所属部门）
5. **合理提炼（须标注）**：仅允许从「通报事由」提炼「通报关键词」；提炼结果必须在摘要里标明「自动提炼」，用户可改

填充规则：

- 能唯一确定的字段 → 直接预填，**不要**再问一遍「是不是这个」
- 有歧义（多名同名、多个可选类型）→ 列入「待确认」，给出候选让用户选，不算已填
- 完全没有线索 → 列入「待补全」
- **禁止编造**：无依据不得猜责任人、部门、积分、类型、分类、数量、奖惩

输出一张内部清单（可对用户展示精简版）：

```text
【行政通报 · 字段预填】
已自动填充:
- 通报类型: …
- 通报责任人: …
- …
待补全（请回复）:
- 提议积分: （未提及）
- 奖惩情况: （未提及）
```

### 2. 仅补全缺失项

- 只追问「待补全 / 待确认」项；已填充项默认沿用，除非用户主动改。
- 尽量**一条消息问清全部缺口**，避免连环单问。
- 用户补全后更新清单；11 项仍不齐则不得进入创建。
- 用户说「按你填的发 / 其余没有」时：仍须确认数字类（提议积分、通报数量）与选项类有合法值；没有则继续要。

### 3. 定位模板

通过钉钉连接器：

- 列出/搜索可发起表单，关键字「行政通报」「行政通告」
- 精确名称「行政通报」优先；多个命中则列出名称 + processCode 请用户选
- [references/form-mapping.md](references/form-mapping.md) 已配置 `processCode` 时直接用
- 找不到：停止，提示检查 OA 后台模板与发起权限
- 勿用待办、日历、日志接口代替 OA

### 4. 拉 Schema 并校验

用连接器按 `processCode` 取表单 Schema（如 form-schema）。

- 用控件 **id / name** 填值，不要只靠中文 label
- 单选/多选 value 必须落在 Schema 枚举内；上下文说法与选项不一致时，映射到最接近选项并在摘要中注明，无法映射则追问
- 「通报责任人 / 提议人」按人员控件要求传用户 ID 或连接器指定结构
- 「责任人所属部门」按部门控件要求传部门 ID；若仅有名称，先用通讯录解析再填

### 5. 组装表单值

```json
[
  { "name": "控件id或唯一名", "value": "字符串值" }
]
```

复杂控件（人员、部门、明细）按 Schema / 连接器文档。映射表见 `references/form-mapping.md`。

### 6. 流程预测（按需）

有自选审批人/条件分支时先 forecast，展示可选人，用户确认后再写入创建参数。

### 7. 确认摘要（须列出 11 项）

```text
即将发起「行政通报」审批
- 模板: {formName} ({processCode})
- 通报类型: …
- 通报责任人: …
- 责任人所属部门: …
- 通报关键词: …（自动提炼则注明）
- 提议人: …
- 提议积分: …
- 通报事由: …（可摘要，完整内容已入表）
- 责任类型: …
- 通报分类: …
- 通报数量: …
- 奖惩情况: …
- 审批路径: …（如有预测）
请回复「确认发起」或指出要改的字段。
```

### 8. 创建实例

用户确认后调用连接器创建审批实例（如 create-instance）。

成功后回复：`instanceId`、关键字段摘要、提示在钉钉「OA 审批 → 我发起的」核对。

失败：原样给出错误，对照 Schema 修正后重试；禁止静默改字段再发；禁止未成功却声称已发起。

若连接器**无发起类工具**：仍完成预填与摘要，给出可粘贴填表清单 + processCode，说明需手工提交或管理员开通；不得伪造 instanceId。

## 对话约定

1. **上下文优先**：先抓取、预填，再只问缺口；不要一上来甩 11 个空表单。
2. 先展示预填/摘要，再调连接器写操作。
3. 默认一次一张单；批量须明确授权。
4. 行政通报以 OA 为准，不用群消息/待办代替。
5. 不代他人发起（除非连接器与权限支持且用户要求）。

## 安全

- 创建/同意/拒绝/撤销须确认（见上）。
- 不输出 access_token、clientSecret。
- 附件仅使用用户明确提供的文件。
